# Embedded browser workflows

The v0.3 overlay reads and writes through the host collaboration adapter. It needs no management app, separate Huddle login or product service. The server remains responsible for authorization, authorship, validation, limits and CSRF protection.

Thread, reply and history controls replace one page at a time. First/next navigation remains available beyond the old display caps. Pending reads disable paging and announce busy state. Expanded history shows its complete structured payload; captured source/context is available without dumping the host DOM. Type `@` in a comment or reply to search the host-approved directory. Suggestions filter as you type, support Arrow keys/Enter/Escape and composition input, and page without displaying a full member checklist. Selected mentions remain visible as removable chips, including across directory pages and restored drafts. Deleting a newly inserted mention from the text removes its notification metadata. The composer limits selection to thirty members. Assignment and historical-author mapping use separate, deliberately opened directory controls. Directory responses accept only member ID/name plus an optional cursor; host account records must not be returned directly.

Open **Transfer feedback** using the named transfer icon in the panel header. Separate Export and Import tabs show one workflow at a time. Export defaults to a complete JSON copy; choose Markdown for reading, and open **Choose what to include** for optional filters. Exports select explicitly authorized environment IDs, JSON or escaped Markdown, and optional page/status filters. A browser download is created after receiving the bounded complete response. JSON must have the supported schema, complete footer and matching record counts. Interrupted/invalid downloads do not become downloadable complete datasets. Host exports use a consistent snapshot; see [host transfers](host-transfers.md).

Import progresses through Choose file, Review and Import. Advanced environment/origin and historical-author mapping controls are collapsed until needed. An import stages a selected JSON file, then previews source scope/record counts, environment/origin mappings, historical identities and conflicts. Mapping changes invalidate the preview and require another preview before execution. Identity choices come from the host-approved directory; a historical name grants no access. Execute is explicit. Each acknowledged request advances one bounded host batch; an uncertain response stops automatic advancement. Resume reuses the same preview, digest, job and request key. Reopening a retained job performs a read-only progress check. A stalled job pauses with a visible message. Completed counts are checked against the preview; a false completion response is an error.

Default upload/download assembly limits are 32 MiB / 64 MiB. Configure `transferLimits: {uploadBytes, downloadBytes}` within maxima 64 MiB / 1 GiB and matching host/proxy limits. Fragmented streams are coalesced into 64 KiB blocks; these are bounded in-memory file operations, not constant-memory streaming to disk. Larger datasets require a smaller export scope or an application-specific transfer tool. File bytes never enter draft storage. Closing, navigation, identity change, revocation and destroy cancel owned UI operations; published discussion stays on the host.

Polling defaults to ten seconds while review is active and the tab is visible, including a collapsed sidebar, with one request at a time and bounded backoff/jitter. Open, reconnect and visibility return catch up immediately. Subscription failures fall back to polling. Draft and uncertain-write state are isolated by integration namespace, workspace, actor, environment and page. Local persistence has bounds/expiry and memory fallback; sensitive hosts can select memory-only or disabled persistence. Authentication denial clears private rendered content. Sign-in belongs to the host.

Capture hooks apply before persistence: `excludeElement` rejects sensitive targets, `redact(text, field)` handles all captured anchor/context strings, `pageIdentity` receives a sanitized URL and `viewContext` supplies bounded JSON. Private descendants/ancestors, form controls and excessively broad target subtrees are rejected. Selection quotes are limited to the selected target. Query/hash retention is opt-in. Stored view context does not restore tabs, dialogs or records automatically. Frame contents, closed shadow DOM and canvas internals remain inaccessible.

The overlay uses Shadow DOM, a host-provided CSP style nonce and native top-layer behavior. By default a mounted widget begins active and collapsed: the dock stays visible at the bottom right and authorized pins load without first expanding the sidebar. There is no dismiss/close button. Expand/collapse uses a short transition and respects `prefers-reduced-motion`. Drag the dock by its grip; keyboard users can move it with Arrow keys (Shift for larger steps), and Home resets its position. Its saved position is bounded to the viewport on resize. Page interaction outside the actual controls is unaffected.

`launcher: 'hidden'` retains the host-controlled opt-in lifecycle: no initial dock or reads until `open()`. The public `close()` method still pauses review, clears rendered private state and stops updates; the normal floating dock remains available to restart. `destroy()` removes the installation. These host APIs are distinct from collapsing, which retains pins, drafts and authorized updates. A host launcher or a pin expands the sidebar. Focus returns to the original host opener on a programmatic close, including an opener in an accessible shadow root.

Pins use Lucide speech-bubble shapes, numbered labels and bounded plain-text previews on hover/focus. Hidden-target badges use Lucide's slashed-eye icon with a descriptive accessible name. Escape dismisses a mention suggestion or preview first, cancels a picker next, and otherwise collapses the sidebar. Workspace/environment metadata is under **Review details**; utility icons retain accessible names and title hints. Focus indicators, live status and busy announcements remain present. Pin selection intercepts page clicks only while deliberately active. Destroy cancels owned animations, DOM/listeners/timers/route hooks and clears detached private UI.

When the host declares `capabilities.commentColors`, the composer offers six named palette choices. A thread keeps its initial pin color and replies retain their own colors. Colors are stored with feedback and survive transfers, not just browser preferences. The last choice is a local convenience for the next comment. Hosts without the capability receive ordinary uncolored writes. Upgrade paired browser/host readers before enabling colors or importing colored data; older strict v2 readers reject the added optional fields. See [the collaboration contract](collaboration-contract.md).

Reviewer names always come from the host. Anonymous hosts can issue a friendly generated identity once per visitor session using the server-only `createAnonymousIdentity()` helper. They keep its ID stable and may expose a public display-name policy. A browser integration can supply `onDisplayNameChange(name, signal)` to update that host profile. The footer then offers an editable name field whose placeholder is the current host-issued name; blank input requests the host's anonymous default. The host must validate and protect the update and return the new name on the next session read. A display name is not an account, unique identifier or access grant. Huddle does not create a login or trust an author ID from the browser. Historical comments retain their recorded names.

Set variables on the Huddle root or an inherited host ancestor. No host stylesheet reset is required.

| Variables | Purpose |
| --- | --- |
| `--huddle-font-family`, `--huddle-color-scheme` | Typography and native control color scheme |
| `--huddle-text`, `--huddle-muted`, `--huddle-link` | Text colors |
| `--huddle-background`, `--huddle-surface`, `--huddle-hover`, `--huddle-border` | Panel and control surfaces |
| `--huddle-accent`, `--huddle-accent-hover`, `--huddle-accent-text`, `--huddle-focus` | Actions and visible focus |
| `--huddle-notice-background`, `--huddle-error-background`, `--huddle-error-text` | Notices and failures |
| `--huddle-badge-background`, `--huddle-target-background`, `--huddle-warning` | Review metadata and anchor warnings |
| `--huddle-panel-width`, `--huddle-radius` | Panel geometry |

Automated accessibility checks and short resource measurements cover the tested browser/fixture combinations. They do not establish every screen-reader/device combination or hours-long performance. Actual versions, measurements, limitations and failed/unavailable gates belong in the implementation evidence, not inferred from old server benchmarks.

The real-host resource check performs twenty mount/open/destroy cycles, waits closed for fifteen seconds (longer than a polling period), then samples an authorized large discussion in thirty-second windows. Chromium supplies forced-GC heap/listener/task metrics; unavailable metrics are null in other browsers. After building the maintained browser fixtures, run an optional bounded ten-minute sample:

```sh
HUDDLE_RESOURCE_SECONDS=600 pnpm exec playwright test tests/browser/resources.spec.ts --project=chromium
```

The override accepts 30–1,800 seconds in thirty-second increments. Default suite samples remain 120 seconds in Chromium and thirty seconds in Firefox/WebKit. Raw reports under ignored `output/browser/resources` identify actual source/versions, request counts, storage and teardown deltas. This is a disposable loopback host with no inference or production database access.
