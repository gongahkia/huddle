A transactional scope fence serializes concurrent changes through bounded retries of definitely aborted write attempts. Snapshot/majority/primary transactions preserve atomic feedback/audit/change/retry state. Cancellation drains native operations before ending sessions; public cancellation can return while owned cleanup drains, and backend close awaits that cleanup. Host hooks receive raw scope, denial stays typed, and closing storage does not close the host client. MongoDB's configured server transaction lifetime remains an independent snapshot limit; transfer jobs/stream acceptance is still pending and must account for it.

## Stage 5 — complete host transfers and real portability

Implemented consistent JSON/escaped Markdown export, bounded upload staging, validated preview, deliberate resumable execution, actor-bound progress, permanent provenance and explicit expired-staging cleanup in ReviewStore. All four real backends support these operations; the host's own session/pool/authorization remains the boundary. No product service, worker, account provisioning or source-URL fetching was added. The host transfer guide documents the protocol, bounds, retry behavior and cleanup procedure.

Exports pin one backend snapshot, validate complete selected records/counts/references and use a one-record backpressure window. Their completeness footer is emitted only after snapshot success. Shared tests cover concurrent writes, revocation, cancellation, failed snapshot completion, corrupt summaries and ambiguous IDs. Imports validate a bounded UTF-8 file before sealing 64 KiB chunks, preview mappings/conflicts, then commit one acknowledged record batch per execute request. GET progress is read-only. A thread header publishes after its child batches; partial children remain invisible through review reads.
