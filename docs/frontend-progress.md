## Stage 3: SQLite core storage

The shared HTTP schemas now also validate server inputs; generated published schemas are unchanged by that extraction.

The SQLite implementation installs additive schema version 1 explicitly and refuses to invent an upgrade. Opening it requires an existing WAL database with valid metadata. Separate bounded collections hold discussion, comments, history, changes, compact request results and future transfer-job/provenance data. There is no new Huddle identity database. Scoped reads use indexes and bound parameters; continuation cursors are authenticated and bound to scope/filter/collection. Write/audit/change/retry state commits in one transaction. Read-only connections pin snapshots while writers continue. Cancellation and close release owned queued work and snapshot connections. Newly created files use mode 0600; existing data/permissions remain under host control.

## Stage 3: MySQL core storage

Added the server-only `@huddle/host/mysql` export using the existing host pool through a structural mysql2/promise-compatible interface. It has no runtime driver import. Explicit additive installation uses dedicated configurable-prefix tables and schema version 1; opening validates existing metadata/tables without DDL. All tables must be InnoDB/utf8mb4_bin, with utf8mb4 client/connection/results and strict SQL mode. Lossy or nontransactional configurations fail visibly. Scope/page/actor hash indexes retain exact encoded-text checks; binary keys and JSON text preserve deterministic paging, Unicode and control characters.

Writes serialize on an InnoDB scope-clock row and commit discussion, audit, change and retry records together. Repeatable-read snapshots retain a consistent view during concurrent commits. Host query guards receive raw scope. The adapter restores the session lock timeout and leaves the host's default isolation unchanged. MySQL lock timeouts have whole-second granularity. Cancellation destroys the owned checkout, releases late pool checkouts and leaves the host pool usable. Installation is explicitly reentrant rather than atomic: MySQL DDL commits implicitly, so the version marker commits only after all tables validate. Unknown versions fail instead of guessing an upgrade.

## Stage 3: MongoDB core storage

Added `@huddle/host/mongodb`, using the host's existing MongoClient/database and common ReviewStore authorization. The driver is a pinned optional type peer (mongodb 7.9.0), with no driver runtime import in the package. A mismatched client/database fails before work. Explicit reentrant installation creates dedicated ordinary collections and indexes with simple collation and marks schema version 1 only after validation; opening never performs DDL. Unknown versions fail. Standalone MongoDB is rejected; this result covers a transaction-capable replica set, not sharded or standalone deployment.

Separate bounded records store discussions, comments, history, events, requests and future transfer state. Scope/id uniqueness and scope/order/thread/status/page/actor indexes cover the common contract. Opening rejects missing or weakened required indexes, including partial/sparse/TTL changes. JSON text retains Unicode/control strings without interpreting Mongo operators or requiring BSON-compatible context field names. A transactional scope fence serializes concurrent changes through bounded retries of definitely aborted write attempts. Snapshot/majority/primary transactions preserve atomic feedback/audit/change/retry state. Snapshot callbacks run once, including after transient read failure, so streaming output cannot silently replay. Unknown commit outcomes still require the original explicit request key.

The pinned driver deprecates timeoutMS as a no-op. The adapter uses explicit abort deadlines and requires finite positive host selection/connection/socket timeouts no larger than its write deadline. Cancellation drains native operations before ending sessions; public cancellation can return while owned cleanup drains, and backend close awaits that cleanup. Host hooks receive raw scope, denial stays typed, and closing storage does not close the host client. MongoDB's configured server transaction lifetime remains an independent snapshot limit; transfer jobs/stream acceptance is still pending and must account for it.

Real MongoDB 8.0.38 / driver 7.9.0 verification passes 29 checks: the shared 15 core tests plus explicit setup/reopen/reinstall, separate-instance concurrency, Unicode/control/operator-looking content, lost acknowledgement after actual COMMIT, standalone denial, missing/weakened indexes, guard denial, client/network prerequisite checks, cancelled partially staged writes and late callbacks, snapshot deadlines, real server outage, an actual server-blocked insert cancelled before commit, and a server-injected transient snapshot error without callback replay.
